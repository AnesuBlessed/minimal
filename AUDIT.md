Full audit of Minimal — 2026-10-15

The visual direction is coherent, and the principal configuration files parse successfully. The repository is not yet a safe, reproducible standalone installation: deployment, rollback, missing session components, and dependencies on the existing HyDE installation need attention first.

This audit covers every project text/configuration/script file, the tracked-file inventory, all 39 saved screenshots/reference images via contact sheets, and image integrity checks across 154 image entries: 108 wallpapers, six character assets plus their `current.png` symlink, and those 39 screenshots/references. Images were also visually surveyed on contact sheets; this is not a pixel-by-pixel review of every wallpaper.

The existing Fuzzel modification was preserved. Fuzzel palette values, `quickshell/hyprquickpaper/shell.qml`, and PROGRESS.md changed externally during the audit, culminating in commit `9438e46`. Those changes were reread; the revised 180 ms carousel and latest launcher configuration were validated again. The carousel layout issue originally found was fixed by that external change and is marked resolved below. No application configuration was edited, no real deployment/restore was run, and no live process was restarted or signalled by this audit. This report is the only project file added.

**What is actually running**

The machine runs Hyprland 0.56.2 with a 1366×768, scale-1 internal display. Its real `~/.config/hypr/hyprland.lua` loads HyDE and `hyprland-gui`, rather than this repository's Hyprland entry point. Waybar runs with explicit paths into this repository. Fuzzel's configuration directory is symlinked into this repository. The live notification and wallpaper processes are Dunst and awww-daemon.

Foot, footclient, Mako, Hyprpaper, brightnessctl, and bluetuith were absent from PATH. Kitty and blueman-manager were present. Thus the screenshots and successful current session do not validate the repository's proposed startup sequence.

**Priority findings**

1. **High — rollback does not restore the pre-install state.** [restore.sh:29](/home/anesu/Projects/minimal/restore.sh:29) omits `dunst`, although [deploy.sh:43](/home/anesu/Projects/minimal/deploy.sh:43) replaces it. Restore also only acts on components with a backup directory: components that did not exist before installation remain installed. In fixtures, restoring a completely fresh installation left all seven symlinks in place while reporting success; restoring existing configurations left Dunst replaced. Existing symlinks are dereferenced during backup, so their link identity is lost on restore. Record each component's original state, including absence and symlink targets, and restore from that manifest.

2. **High — a partial backup failure is incorrectly treated as recoverable success.** At [deploy.sh:48](/home/anesu/Projects/minimal/deploy.sh:48), failed `cp -rL` falls back to `mv` into the same destination. If copying has already created a partial directory, `mv` nests the original inside it. A simulated copy failure produced `backup/hypr/hypr/original`; deployment and restore both returned zero, but the original file was not restored to its expected location. Backups should be staged and verified before removal/replacement, with failure leaving the original untouched. The current remove-then-link sequence is also not atomic and has no automatic rollback on later failures. Timestamp names have only second precision and there is no concurrency lock.

3. **High — deployment removes the existing lock and idle configuration without replacements.** Deployment replaces the entire `~/.config/hypr` directory, but this repository contains neither `hyprlock.conf` nor `hypridle.conf`. Startup nevertheless launches `hypridle`, and bindings plus the bar invoke `hyprlock`: [hypr/hyprland.lua:49](/home/anesu/Projects/minimal/hypr/hyprland.lua:49), [hypr/keybinds.lua:62](/home/anesu/Projects/minimal/hypr/keybinds.lua:62). The actual machine currently has both configuration files outside the repository. A deployment fixture confirmed their disappearance from the active config tree. Supply tested configurations or deliberately preserve them. The real desktop was not locked/suspended to test this; upstream Hyprlock explicitly reports an error when it cannot find a configuration. [Hyprlock configuration source](https://raw.githubusercontent.com/hyprwm/hyprlock/main/src/config/ConfigManager.cpp).

4. **High — the deployed Waybar CSS import fails.** [waybar/style.css:10](/home/anesu/Projects/minimal/waybar/style.css:10) imports `../colors.css`. Loading the stylesheet as `~/.config/waybar/style.css` resolves that import to `~/.config/colors.css`, which deployment does not create. GTK loading through a temporary symlink reproduced “Failed to import … config/colors.css: No such file or directory.” Loading via the repository's real path succeeded, explaining why the explicitly launched live bar works. Keep the imported palette within the deployed component or otherwise ensure the import target is installed. Waybar's upstream loader passes the selected path to GTK rather than canonicalizing it first. [Waybar CSS loader](https://raw.githubusercontent.com/Alexays/Waybar/master/src/client.cpp), [configuration path lookup](https://raw.githubusercontent.com/Alexays/Waybar/master/src/config.cpp).

5. **High — startup does not match the implemented desktop.** [hypr/hyprland.lua:40](/home/anesu/Projects/minimal/hypr/hyprland.lua:40) starts Foot, Mako and Hyprpaper; all three are missing locally. The wallpaper scripts use awww, but this startup configuration never starts awww-daemon. [deploy.sh:25](/home/anesu/Projects/minimal/deploy.sh:25) only warns about some missing dependencies and proceeds; it omits others, including Hyprpaper, Waybar, hypridle, hyprlock, jq, Python/Pillow, and the utilities used by keybindings. A fresh session under this configuration cannot reproduce the current setup. Choose the intended daemon stack and check all required binaries before modifying configuration.

6. **Medium — Dunst's saved configuration is not a standalone Dunst entry point.** The repo ships `dunst/dunst.conf`, but plain Dunst searches for `dunst/dunstrc` or its documented drop-ins, unless given an explicit config path. The real machine's `dunstrc` is generated by HyDE from a template; that generation step and generated palette/font settings are not deployed here. The saved template has no active font assignment or urgency palette sections. Simply adding `dunst` to startup would not reproduce the showcased notifications. Install a complete `dunstrc` or launch with a complete explicit config. [Dunst configuration search documentation](https://dunst-project.org/documentation/dunst/).

7. **Medium — theming relies on undeclared HyDE state and is not unified.** [colors.css:9](/home/anesu/Projects/minimal/colors.css:9) imports `/home/anesu/.cache/hyde/wallbash/gtk.css` with no fallback. A different account or fresh cache lacks this file. `hyde-shell` is optional in the wallpaper scripts, although it supplies the palette machinery this design depends on. Hyprland's `colors.lua`, Foot, Mako, the carousel border, and the calendar retain independent fixed colors. There is no repository code updating `colors.lua`. Provide a bundled base palette and either make HyDE an explicit prerequisite or implement a self-contained generation path.

8. **Medium — wallpaper operations report success even when application fails.** [quickshell/hyprquickpaper/commands.sh:5](/home/anesu/Projects/minimal/quickshell/hyprquickpaper/commands.sh:5) and [scripts/wallchange.sh:16](/home/anesu/Projects/minimal/scripts/wallchange.sh:16) write the selected path and send success notifications regardless of awww's exit status. A mocked failing backend still produced “Wallpaper Applied,” persisted the selection, and exited zero. The state file `~/.config/minimal/current_wallpaper` is never read by repository startup code; Hyprpaper instead uses an unrelated fixed image. Only persist/report success after a successful application, and restore the selection at login with the chosen backend.

9. **Medium — toggling the picker can terminate unrelated Quickshell components.** [scripts/wallchange.sh:34](/home/anesu/Projects/minimal/scripts/wallchange.sh:34) uses `pkill -x quickshell`. This targets every accessible process with that name, rather than this carousel alone. If another Quickshell widget is running, the shortcut kills it and exits without opening the picker. Use instance-specific control or a managed PID. Static finding; no live processes were killed to reproduce it.

10. **Resolved during audit — carousel layout mismatch corrected externally.** The initial implementation computed navigation positions with a fixed stride but varied each delegate's width, which could miscenter selection and cause drift. Commit `9438e46` changed [shell.qml:196](/home/anesu/Projects/minimal/quickshell/hyprquickpaper/shell.qml:196) to a fixed `baseWidth` slot and scales the child instead. That addresses the source-level mismatch; the revised file passes `qmllint`. The wheel accumulator, cooldown and click-to-select behavior were also reviewed. Remaining low-priority robustness gaps: empty-model activation and zero/invalid `number_of_pictures` lack guards. Current interactive behavior was not exercised by this audit.

11. **Medium — launcher fallback stops at an unavailable Foot server.** [fuzzel/fuzzel.ini:19](/home/anesu/Projects/minimal/fuzzel/fuzzel.ini:19) checks whether `footclient` exists, then runs it without falling back if connection fails. With a mock installed footclient that returned failure, the configured command exited 1 and never invoked Foot. Use fallback on command failure, not executable presence alone. The Super+T binding already uses a failure-based fallback, but both its candidates are currently absent.

12. **Medium — cancellation can still write an empty clipboard.** [hypr/keybinds.lua:55](/home/anesu/Projects/minimal/hypr/keybinds.lua:55) pipes the picker into decode and `wl-copy` without guarding cancellation. A mocked cancelled picker still invoked the clipboard writer with zero bytes and the pipeline returned success. The screenshot pipelines at lines 69–70 similarly do not guard failed/cancelled region selection before starting downstream consumers. Capture and validate the selection first. Tests used mocked clipboard commands; the real clipboard was untouched.

13. **Medium — the wallpaper collection is incomplete in Git.** [.gitignore:2](/home/anesu/Projects/minimal/.gitignore:2) ignores all PNGs except Fastfetch assets. Only 60 of 108 wallpapers are tracked; the other 48 PNG wallpapers will be missing from a fresh clone. Exempt `wallpapers/*.png` or document a deliberate external asset installation step.

14. **Medium — portability depends on the username, checkout location and hardware.** Fixed paths occur in `colors.css`, `fastfetch/config.jsonc`, the `current.png` symlink, `hypr/hyprpaper.conf`, the wallpaper keybind, the palette updater, and the carousel config. [waybar/config.jsonc:114](/home/anesu/Projects/minimal/waybar/config.jsonc:114) fixes `intel_backlight`, and lines 162–163 fix `BAT0`/`AC`. The monitor fallback is generic, but these other settings are not. Use paths derived from the installation and discover or override device names. The random wallpaper array in [scripts/wallchange.sh:13](/home/anesu/Projects/minimal/scripts/wallchange.sh:13) also splits filenames containing whitespace; none of the current wallpaper basenames contain spaces, but moving the checkout to a spaced path exposes it.

15. **Medium — palette writes can fail midway and race.** [scripts/update_fuzzel_colors.py:61](/home/anesu/Projects/minimal/scripts/update_fuzzel_colors.py:61) truncates and rewrites the source config directly. It then calls `samefile()` on the destination before checking that it exists. A fixture with no deployed destination reproduced `FileNotFoundError` after the source was already changed. Multiple background wallpaper jobs can overlap and rewrite colors out of order; callers suppress errors. Generate to a temporary file, replace atomically, guard missing destinations, and serialize or discard superseded palette jobs.

16. **Low — thumbnail cache is stale by filename and fragile with quoted paths.** [quickshell/hyprquickpaper/cache.sh:19](/home/anesu/Projects/minimal/quickshell/hyprquickpaper/cache.sh:19) skips any existing output regardless of source modification time. Replacing a red test wallpaper with a blue image of the same name left the thumbnail unchanged. Lines 12–13 interpolate paths into Python source: an apostrophe in a configured path reproduced a Python syntax error. Pass paths as arguments and invalidate thumbnails on source changes. Cache exceptions are otherwise silently ignored; the UI retries image errors every second while open without an eventual failure state. The declared `cache_batch_size` is unused, and the random selector accepts WebP while the carousel filters only PNG/JPG.

17. **Low — documented performance and design requirements are inconsistent with the files.** The repo enables two-pass compositor blur despite RULES.md forbidding it; the bar adds a shadow and 150–200 ms transitions; the revised carousel uses 180 ms, beyond the stated 100–120 ms cap; Fuzzel has radius 14 against the stated 8–10 px cap. These are policy/design discrepancies, not measured proof of poor performance. The live compositor actually reported blur disabled, further demonstrating that the repository config is not the live one. The documentation's “0 ms,” “sub-millisecond,” “0 MB,” and hardware-universal claims are not supported by benchmarks or the deployment checks.

18. **Low — documentation overstates completion and some UI intent is unclear.** PROGRESS.md's phase tracker still describes configurations and dependencies that have changed, calls deployment atomic, and promises complete rollback. New entries added during the audit correctly document hicolor and carousel changes, but the older completion claims remain misleading as a current setup guide. Fastfetch's character-selection utility is present, but no repository shell-startup integration invokes Fastfetch or randomizes the character automatically. The bar's power icon only locks the screen, with no tooltip explaining it. These should be documented according to actual behavior.

**Limits and reproducibility**

Deployment and restore were executed only against disposable fixture directories. Copies of those scripts changed only their `CONFIG_DIR` assignment to the fixture path; project component folders were represented with marker files. Failure tests injected a failing copy command or mocked application binaries. HOME and the actual configuration directories were not redirected or modified. The CSS fixture symlink pointed at the real, unchanged repository stylesheet.

Raw fixture outcomes and source hashes are available for this local session in `/tmp/minimal-audit-s582plq8/results.json` and `/tmp/minimal-audit-s582plq8/source-sha256.json`. Contact sheets are in that same temporary directory. These temporary artifacts are not part of the repository and may disappear after cleanup/reboot.

No fresh login, real deployment, actual rollback, lock/unlock, suspend/resume, external-monitor/high-DPI run, interactive carousel test, or power/GPU benchmark was performed. Foot and Mako could not receive native runtime validation because their binaries are absent. ShellCheck is also absent. A syntax pass does not establish successful startup or correct interaction behavior.

Fix order: make backup/restore reliable and preserve locking/idle behavior; settle the intended daemon stack; repair deployed palette paths and dependency checks; then address wallpaper/picker behavior, portability, and visual contrast. This order makes the polished desktop reproducible before extending the styling.
